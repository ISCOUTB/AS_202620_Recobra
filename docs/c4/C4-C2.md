# C4-C2: Diagrama de Contenedores — Recobra

Hace zoom sobre el sistema Recobra del [C4-C1](C4-C1.md) y muestra sus
contenedores desplegables y el estado real de cada uno en el código.

Actualizado para el segundo corte (S10): refleja PostgreSQL activo,
Emparejamiento y búsqueda implementados, la vitrina web y el despliegue en
Dokploy. Lo que sigue siendo planeado se marca como tal.

| Contenedor | Estado en código | Notas |
|------------|------------------|-------|
| App cliente Flutter | Implementado | `mobile/` — crear, consultar y ver coincidencias |
| Vitrina web | Implementado | `public/index.html`, servida por la propia API; publicar, buscar con filtros y ver coincidencias |
| API backend NestJS | Implementado | Publicaciones (`POST/GET /publicaciones`, búsqueda con filtros), Emparejamiento (`GET /coincidencias`), `/health` y `/metrics` |
| PostgreSQL | Implementado | `PostgresPublicacionRepository` se activa con `DATABASE_URL`; sin ella la API usa memoria ([ADR-0006](../adr/0006-plataforma-persistencia-postgresql.md)) |
| Coincidencias | Implementado en memoria | `MemoriaCoincidenciaRepository`: se pierden al reiniciar la API; pendiente de persistir |
| Notificaciones / Auth | Planeado | Aparecen en C4-C1; aún no son contenedores con código |

## Despliegue

La API se empaqueta con el [`Dockerfile`](../../Dockerfile) y se despliega en
Dokploy mediante [`deploy/compose.lab.yaml`](../../deploy/compose.lab.yaml);
el detalle del entorno está en la
[sección 7 de arc42](../arc42/arc42.md#7-vista-de-despliegue). Render dejó de
usarse (ver el ADR de migración a Dokploy en `docs/adr/`).
